# AI admin builder (watsonx Orchestrate agent `tenderflow_admin_builder`)

An entity administrator describes a configuration change in plain language — in Arabic or English — and the watsonx
Orchestrate agent **`tenderflow_admin_builder`** turns it into a structured **change proposal**. TenderFlow validates every
operation with its own server validators, shows the administrator exactly what would change, and creates **DRAFTS only**
when the administrator clicks **Create drafts**. Publishing stays a human click in Cycle Designer / Process Studio.

Examples it handles:

| Request | Proposed operation(s) |
|---|---|
| "Create a two-envelope RFP template with a 60/40 technical/price split and a pass mark of 70" | `CREATE_TEMPLATE` (two envelopes, pass mark 70, financial criterion `price`). The 60/40 weights are entered per tender (Evaluation criteria); the agent says so. |
| "Tenders above 1,000,000 KWD need the Undersecretary" | `ADD_RULE` — gate `TENDER_SUBMIT`, `tender.estimatedBudget > 1000000`, `ADD_APPROVER UNDERSECRETARY` |
| "Add a required 'Project code' field to the tender form" | `ADD_FORM_FIELD` on `TENDER` (`projectCode`, text, required) |
| "Remind officers 72 hours before the deadline" | `ADD_RULE` — schedule `DEADLINE_APPROACHING` (`hoursBefore: 72`), `NOTIFY PROCUREMENT_OFFICER` |
| "Strategic projects must upload a risk register before publication" | `ADD_RULE` — gate `TENDER_PUBLISH`, `tender.custom.strategicProject isTrue`, `REQUIRE_DOCUMENTS titleContains "risk register"` |
| "Make it 2 million instead" (follow-up) | The same proposal is revised on the same Orchestrate thread (revision 2) |
| "Give Ahmed the director role" | No operations: users and roles are done in **Admin → Identity & access / Accounts** |

## Where it is

- **Admin → AI builder** (`/admin/builder`): conversation on one side, the proposal on the other — one card per operation
  with a plain-language sentence (EN/AR, computed by TenderFlow from the validated values, not the agent's wording), a
  validation badge, reasons and warnings, and a field-level diff ("Show the exact change"). Buttons **Create drafts** /
  **Discard**; after applying, links to the created drafts. Proposal history below. `?proposal=<id>` opens a proposal.
- **`<DescribeChangeButton scope="template" | "process" | "forms" />`** (`apps/web/src/features/adminagent`): a compact
  modal version shown as **Describe a change** in the Cycle Designer header (`scope="template"`) and the Process Studio
  header (`scope="process"`) since rc6 (props: `scope`, optional `onApplied(refs)`, `label`, `variant`; renders nothing
  for non-administrators). After **Create drafts** the page reloads so the new drafts appear.
- **Assistant dock**: administrators see a "Build with AI" entry that opens the page.

## Safety model

1. **Draft-first.** The agent only proposes. Nothing is written to the configuration when a proposal is made. Applying
   creates or edits **DRAFT** versions only (document types are created **switched off**). Publishing is a separate human
   step in Cycle Designer / Process Studio, under the entity's four-eyes setting (`configFourEyes`: the last editor of a
   draft — i.e. the administrator who applied the proposal — cannot publish it).
2. **Same rules as the screens.** Every operation is validated by the existing validators — `parseConfig`
   (cycle templates), `validateFormDefinition` (forms), `validateRuleset` (rules, against the catalogue and the entity's
   forms and integrations), the document-type parsers — against the entity's current configuration plus the earlier
   operations of the same proposal. A proposal can be applied only when **every** operation is valid. It is validated
   again inside the apply transaction, so a configuration that changed in the meantime is caught (409 `PROPOSAL_INVALID`).
3. **Locked controls cannot be touched.** Bid encryption, chair-only opening after the deadline, approver ≠ creator, one
   person one level, recommender ≠ award approver and the audit chain are not configurable anywhere. Rules can only add
   controls; there is no action that removes an approval, opens a bid or edits the audit trail. Unknown template settings
   (e.g. `integrity`) and unknown rule actions (e.g. `OPEN_BIDS`) are refused with a bilingual explanation.
4. **Strict contract.** The agent must return `{"reply":{"en","ar"},"operations":[…],"questions":[…]}` with only the nine
   operation types and their documented keys. Anything else triggers one repair turn on the same thread, then a clear
   error (502 `AI_ERROR`, recorded as a failed AI run) — no proposal is stored.
5. **No simulated AI.** Not configured → 503 `AI_NOT_CONFIGURED`; agent not imported → 503 `AI_AGENT_NOT_IMPORTED`; the
   page shows the corresponding banner. Nothing is generated by TenderFlow itself.
6. **Own entity only.** The entity comes from the token. Every query filters by `tenant_id`; the prompt contains only the
   entity's own templates, forms, rules, integration codes and document types (names, codes, keys and settings — no
   webhook URLs or secrets, no tender, bid, vendor or user data). Another entity's proposals return 404.
7. **Permissions.** `TENANT_ADMIN`: chat, submit, apply, discard. `AUDITOR`: read proposals and history. Everyone else: 403.
   Orchestrate threads are bound to the administrator who started them.
8. **Out of scope** (the agent says where it is done, with no operations): users and roles, publishing/approving/opening/
   awarding, editing tenders or bids, notification texts, entity settings (four-eyes, numbering), integrations.

## Operation catalogue (v1)

| Operation | Keys | Applied through | Result |
|---|---|---|---|
| `CREATE_TEMPLATE` | `code` (new), `nameEn`, `nameAr`, `description?`, `baseCode?` (existing or starter template), `changes?` | `insertTemplateDraft` (services/templates.ts) | new template code, DRAFT v1 |
| `NEW_TEMPLATE_VERSION` | `code` (existing), `nameEn?`, `nameAr?`, `description?`, `changes` | `insertTemplateDraft` / `updateTemplateDraft` | next DRAFT version, or the open draft is updated (warning shown) |
| `ADD_RULE` | `rule {id?, nameEn, nameAr, enabled?, trigger, params?, when, actions}` | `insertDraft` / `saveDraft` (lowcode/definitions.ts) | rule set `PROCESS` draft (created from the live version if none is open) |
| `UPDATE_RULE` | `ruleId`, `changes` | same | same |
| `SET_RULE_ENABLED` | `ruleId`, `enabled` | same | same |
| `ADD_FORM_SECTION` | `form` (`TENDER`/`REQUEST`/`VENDOR`), `section {key, titleEn, titleAr}` | same | form draft |
| `ADD_FORM_FIELD` | `form`, `field {key (camelCase), type, labelEn, labelAr, required?, requiredAt?, audience?, section?, …}` | same | form draft |
| `UPDATE_FORM_FIELD` | `form`, `key`, `changes` | same | form draft |
| `ADD_DOCUMENT_TYPE` | `code`, `nameEn`, `nameAr`, `contexts[]`, `fields[]?` | `insertDocumentType` (services/doc-catalogue.ts) | document type, **inactive** |

Template `changes` keys: `scope`, `envelopes`, `stages{requestIntake, documentPurchase, gazette, capt, complianceScreening,
recordsLock}`, `approvals{request, publish, award}` (1–5 levels of DIRECTOR / UNDERSECRETARY / COMMITTEE_CHAIR /
TENANT_ADMIN; missing labels are filled from the role), `evaluation{technicalPassMark, financialCriteria}`,
`eligibility{activityCodes, minGrade}`, `fees{documentPrice, currency, exemptionAllowed}`, `ai{…}`. Objects merge, arrays
replace. Rule facts, operators, triggers and actions are those of the low-code catalogue (`lowcode/catalog.ts`, see
[LOW-CODE-STUDIO.md](LOW-CODE-STUDIO.md)), plus the entity's custom-field facts. Operations are evaluated in a fixed order
(sections → fields → templates → document types → rules), so a rule may test a field added in the same proposal; if that
field is only in a form draft, the card warns to publish the form draft before the rule set.

Not in v1: notification templates (they are edited live, not as drafts) and user accounts/roles (security-sensitive).

## API (`/api/v1`, bearer token)

| Method | Path | Who | What |
|---|---|---|---|
| GET | `/admin-agent/status` | admin, auditor | `{configured, agent{name, checked, imported}, canApply}` |
| POST | `/admin-agent/chat` `{message, proposalId?, threadId?}` | admin | Runs the agent, validates, stores/updates the proposal → 201 proposal. With `proposalId` (or the `threadId` of an open proposal) the same proposal is revised on the same Orchestrate thread. |
| POST | `/admin-agent/proposals` `{request?, reply?{en,ar}, operations[]}` | admin | Structured plan without AI (the Orchestrate tool path): strict shape check (400 on unknown ops/keys), same validation, stored as `source: TOOL`, **never applied** (`applied: false`, `reviewPath`). |
| GET | `/admin-agent/proposals[?status=]` | admin, auditor | Latest 50 proposals of the entity |
| GET | `/admin-agent/proposals/:id` | admin, auditor | Proposal with `operations`, `validation{valid, results[], errors[], notes[]}`, `messages`, `appliedRefs` |
| POST | `/admin-agent/proposals/:id/apply` | admin | One transaction: claim (idempotent; a second apply → 409 `PROPOSAL_ALREADY_APPLIED`), re-validate (409 `PROPOSAL_INVALID` with the new validation), create the drafts, record the refs |
| POST | `/admin-agent/proposals/:id/discard` `{reason?}` | admin | `PROPOSED` → `DISCARDED` |

Each operation result: `{index, op, status ok|error, summary{en,ar}, errors[{en,ar}], warnings[{en,ar}],
target{type, code, action CREATE_DRAFT|UPDATE_DRAFT|CREATE_INACTIVE, draftVersion}, diff[{path, before, after}]}`.
Validator messages from the existing services are English; the Arabic text carries the same message with an Arabic lead-in.

Storage: migration `services/api/migrations/011_admin_agent.sql` — table `admin_proposals` (status `PROPOSED | APPLIED |
DISCARDED | FAILED`, `source CHAT | TOOL`, `operations`, `validation`, `summary`, `messages`, `revision`, `applied_refs`,
`thread_id`, `ai_run_id`), and `ai_runs.kind` `ADMIN_BUILDER` (each agent call is an AI run, OK or ERROR, via `recordRun`).

## Audit events

| Event | When |
|---|---|
| `ADMIN_AGENT_PROPOSED` | A proposal is created or revised (details: source, revision, operation types, valid, invalid operation indexes, AI run id) |
| `ADMIN_AGENT_APPLIED` | Drafts were created (details: the drafts' type, id, code, version, status) |
| `ADMIN_AGENT_DISCARDED` | Discarded, with the optional reason |
| `ADMIN_AGENT_APPLY_FAILED` | An unexpected error rolled the apply back; the proposal is marked `FAILED` |
| `TEMPLATE_CREATED/UPDATED`, `LOWCODE_DRAFT_CREATED/UPDATED`, `DOCUMENT_TYPE_CREATED` | Written by the services for each draft, in the same transaction, with `details.via = "ADMIN_AGENT"` and `details.proposalId` |
| `AI_ADVISORY_GENERATED` / `AI_ADVISORY_FAILED` | The agent call itself (`kind: ADMIN_BUILDER`) |

All are in the HMAC-chained, append-only audit log (`GET /audit/verify`).

## Setup in watsonx Orchestrate

1. Import the agent with the others: `agents\import.ps1` (Windows) or `bash agents/import.sh` — they now import eleven
   agents including `agents/tenderflow_admin_builder.yaml`. Pick a model that is strong in Arabic **and** strict JSON
   (`WXO_LLM`, see [agents/README.md](../agents/README.md)).
2. Optional: `WXO_AGENT_ADMIN_BUILDER=<name or id>` if the agent has another name on the instance (default
   `tenderflow_admin_builder`).
3. `npm run build && npm run verify:ai` — checks that the agent exists and runs one live admin-builder turn (expects an
   `ADD_RULE` for "Tenders above 1,000,000 KWD need the Undersecretary").
4. `npm run evals -- agents` — includes `agents/evals/agents/admin-builder.json` (6 cases, EN + AR, incl. an
   out-of-scope request that must produce no operations).

### Using the same agent from the Orchestrate chat (tool pack)

`agents/tools/tenderflow-admin.openapi.yaml` exposes `submit_admin_proposal` (`POST /admin-agent/proposals`) and
`get_admin_proposal` (`GET /admin-agent/proposals/{id}`). With it attached, the agent submits proposals into TenderFlow from
the Orchestrate chat; an administrator reviews and applies them in TenderFlow. There is no apply or publish tool. It needs
TenderFlow on a public HTTPS URL and a bearer connection holding a `TENANT_ADMIN` token — setup in
[agents/tools/README.md](../agents/tools/README.md).
